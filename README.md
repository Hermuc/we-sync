# WE-Sync

把 Wallpaper Engine 里的**视频壁纸自动同步到手机**。

电脑上订阅的壁纸，手机插上数据线就能收到——不用手动找文件夹、不用装手机 App、不用注册账号。
单文件绿色版：一个 `we-sync.exe`，双击就能用，不写注册表、不装服务、删掉即卸载。

---

## 三步开始

1. **下载** [`we-sync.exe`](../../releases/latest)，放到任意文件夹（U 盘、桌面都行）。
2. **双击运行**。首次启动会自动找到 Steam 里的壁纸库，并生成配置文件。
3. **手机用数据线连电脑**，下拉通知栏把 USB 用途选成「**传输文件 / MTP**」。
   之后程序会自己把壁纸传过去，传完在设置窗口能看到结果。

> 想让壁纸不显示在相册里？默认目标目录是 `/sdcard/.WE`（以点开头的隐藏目录），
> 用 MT 管理器之类的第三方文件管理器勾选「显示隐藏文件」就能看到。

## 它能做什么

| 能力 | 说明 |
|---|---|
| 自动识别壁纸库 | 从 Steam 配置里找到 `steamapps/workshop/content/431960`，不用手填路径 |
| 只传视频壁纸 | 读取每个壁纸的 `project.json`，取其中的 mp4；scene/web 类型自动忽略 |
| 新壁纸自动补传 | 程序运行期间订阅的新壁纸，Steam 下载完成后自动排队上传 |
| 不重复传 | 手机上已有同名同大小的文件直接跳过 |
| 体积过滤 | 只要指定区间内的壁纸（默认不限，可设下限避免传几十兆的小玩意） |
| 队列按大小排序 | 小文件先传完，等待感更小 |
| 托盘常驻 | 关掉窗口可以最小化到托盘，右键有「立即同步 / 暂停 / 打开日志」 |
| 可选双通道加速 | 同时用 USB 和 WiFi 传同一个文件（见下方「进阶」） |

## 界面怎么看

窗口中间三行状态：

| 行 | 含义 |
|---|---|
| `已连接 [MTP] 手机型号 …` | 当前用的通道、设备名、手机存储；未连接时会提示怎么连 |
| `传输中: 文件名 42% (16.8 MB/40.0 MB)` | 当前传输进度，空闲时显示「空闲」 |
| `本次已复制 3 · 手机上已有 12 · 失败 0 …` | 本次运行内的统计 |

四个按钮：

| 按钮 | 作用 |
|---|---|
| **保存设置** | 把界面上的改动写进 `config.toml`，不主动触发同步 |
| **立即同步** | 马上重扫壁纸库并排队（空闲时才可点） |
| **暂停 / 继续** | 中断当前文件（半截文件会被删除），恢复后重传；传输中才可点 |
| **打开工坊目录 / 打开软件目录** | 在资源管理器里打开对应路径 |

「立即同步」和「暂停」是互斥的：同一时刻只有一个亮着，另一个变灰。

## 两种连接方式

| 方式 | 手机侧要做什么 | 实测速度\* | 适合 |
|---|---|---|---|
| **MTP**（默认） | 选「传输文件」即可，不需要开发者选项 | 约 35 MB/s | 日常，插上就用 |
| **ADB** | 需开启「开发者选项 → USB 调试」并授权本机 | 约 31–34 MB/s | MTP 抽风、或需要写更多目录时 |

\* 40 MB 单文件的实测值，取决于机型、数据线和 USB 版本。**不要预设 ADB 一定更快**——有些设备 MTP 只有 5–15 MB/s，有些反而 MTP 领先。

设置窗口里的「传输通道」下拉有四项：

- **自动（按速度择优）**：每次传输都会把两种通道的实测吞吐记进 `sync-state.json`，之后自动选更快的（差距超过 5% 才切换，避免来回抖）。没有数据时先用 MTP。
- **仅 MTP** / **仅 ADB**：固定用其中一种。
- **多通道（USB+WiFi）**：见下方「进阶」。

## 常用设置

改设置窗口里的项即可；也可以直接编辑 exe 同目录的 `config.toml`。

| 设置 | 默认值 | 说明 |
|---|---|---|
| 工坊目录 | 自动探测 | Steam 的 `workshop/content/431960`，一般不用改 |
| 手机目录 | `/sdcard/.WE` | 想让它出现在相册里就改成 `/sdcard/Movies/WE` |
| 体积区间 | 不限 | 单位 MB；上限填 0 表示不限 |
| 只复制 mp4 | 开 | 关掉后按 `project.json` 的 `file` 字段判断 |
| 文件名模板 | `{title} [{id}].{ext}` | 支持 `{title}` `{id}` `{ext}` |
| 跳过已存在 | 开 | 手机上同名同大小就跳过 |
| 启动即同步 | 开 | 关掉后需要手动点「立即同步」 |
| 关窗口最小化到托盘 | 开 | 关掉则直接退出 |

## 常见问题

**手机上找不到文件？**
默认目录 `/sdcard/.WE` 是隐藏目录，系统自带文件管理器看不见。用支持「显示隐藏文件」的文件管理器，或把「手机目录」改成 `/sdcard/Movies/WE`。

**程序提示未检测到手机？**
1. 确认通知栏的 USB 用途是「传输文件」而不是「仅充电」；
2. 在资源管理器里能打开「手机内部存储」，说明 MTP 正常；
3. 仍不行就换 ADB（开 USB 调试，下拉选「仅 ADB」）。

**传输很慢？**
换一条数据线、换 USB 3.0 口试试；首次全量同步可以试 ADB。MTP 对大量小文件本来就慢。

**新订阅的壁纸没传？**
程序会等文件写入稳定（默认 8 秒）并且 Steam 下载结束后才动手。看日志能确认，或者点托盘「立即同步」。

**换手机 / 想重传？**
删掉 `sync-state.json` 再点「立即同步」。手机上已有的文件仍会按「跳过已存在」处理。

**删掉程序会留垃圾吗？**
不会。配置、日志、同步记录都在 exe 同目录，整个文件夹删掉即可，注册表和系统目录一概不碰。

## 进阶：USB + WiFi 双通道

USB 数据线和 WiFi 是两条独立的物理通道，可以同时传同一个文件的不同部分，理论速度接近两者之和。

**开启方式**：设置窗口「传输通道」选「多通道（USB+WiFi）」。

**前提条件**：

1. 手机开「USB 调试」（USB 侧走 `adb forward`，这是唯一能把 USB 变成 TCP 通道的方式；MTP 是设备通道，无法分块）；
2. 手机和电脑连**同一个局域网**，且该网络**没有客户端隔离**（很多学校/公共 WiFi 会禁止设备互访，这种情况会退化成单通道）；
3. `plugins/agent/` 下有与手机 ABI 匹配的接收端二进制。

**必须是绿色、无残留**：程序会把接收端 `adb push` 到手机的 `/data/local/tmp` 直接运行，传输结束 `kill` + `rm`，不安装 App、不需要 root 或 Shizuku、不改任何系统设置。

**注意**：只有一条链路时**不会**启用多通道——单条 USB 走分块协议反而比 MTP 慢（实测约 20 MB/s vs 35 MB/s）。程序会自动回落，不会让你等更久。

接收端需要自己编译（一条命令，不需要 Android NDK）：

```bash
cargo build --release            # 先构建主程序，确保 target/debug/wsync-agent 存在
bash scripts/build-agent-android.sh   # 产物自动落到 plugins/agent/wsync-agent-aarch64
```

如果只想用 USB，保持「自动」或「仅 MTP」即可，完全不需要管这一节。

## 从源码构建

需要 Rust 1.80+（Windows 上用 msvc 工具链）。

```bash
cargo build --release          # 产物：target/release/we-sync.exe
cargo test --workspace         # 单元测试 + 端到端协议测试
cargo clippy --workspace --all-targets
```

`exe` 已通过 `.cargo/config.toml` 的 `crt-static` 静态链接 CRT，不依赖 VC++ 运行库，只用到系统自带的 DLL。

### 代码结构

```
src/
  engine.rs          同步引擎：扫描、排队、传输、探活
  transport/         通道抽象（MTP / ADB / 多通道）
    multipath/       分块并行：planner 选链路、scheduler 发号重派、link 收发、agent 投放
  ui/                Win32 自绘界面（GDI+ 抗锯齿）、托盘、设置
  config.rs          配置（exe 同目录 config.toml）
  state.rs           同步记录（sync-state.json）
  discover.rs        Steam 库 / adb 自动发现
crates/
  wsync-proto/       帧协议 + CRC32 + SHA-256，零外部依赖
  wsync-agent/       手机端接收端（纯 std，可交叉编译到 Android）
scripts/
  build-agent-android.sh   免 NDK 交叉编译（静态 musl + rust-lld）
```

## 排查问题

日志在 exe 同目录的 `logs/we-sync.log`，超过 4 MB 自动滚动一次。

默认只记录 info 级日志。想看详细过程（选路依据、跳过了哪些壁纸、为什么等待），设置环境变量后启动：

```powershell
$env:WE_SYNC_LOG = "debug"
.\we-sync.exe
```

可选 `debug` / `info` / `warn` / `error`。

## 目录里有哪些文件

| 文件 | 必需 | 作用 |
|---|---|---|
| `we-sync.exe` | ✅ | 主程序，约 0.95 MB |
| `config.toml` | 否 | 配置，删掉会按默认值重建 |
| `sync-state.json` | 否 | 已同步记录，删掉会重新比对（已有文件仍跳过） |
| `logs/we-sync.log` | 否 | 运行日志 |
| `tools/adb.exe` | 否 | 只有用 ADB / 多通道时才需要 |
| `plugins/agent/wsync-agent-*` | 否 | 只有用多通道时才需要 |

**最小可用就是一个 exe**。
